# Routing：学习用例大纲与进度

官方章节：[Controllers - Routing](https://docs.nestjs.com/controllers#routing)

## 官方原文（学习依据）

以下原文以本次学习时对照的官方文档内容为依据：

> The following example uses the `@Controller()` decorator, which is **required** to define a basic controller, with an optional route path prefix of `cats`. A path prefix in the `@Controller()` decorator groups related routes and reduces repetitive code. For example, to group the routes that manage cat entities under the `/cats` path, specify the `cats` prefix in the `@Controller()` decorator. You then don't need to repeat that portion of the path for each route in the file.
>
> ```typescript
> import { Controller, Get } from '@nestjs/common';
>
> @Controller('cats')
> export class CatsController {
>   @Get()
>   findAll(): string {
>     return 'This action returns all cats';
>   }
> }
> ```
>
> **Hint** To create a controller using the CLI, run the `$ nest g controller [name]` command.
>
> The `@Get()` HTTP request method decorator placed before the `findAll()` method tells Nest to create a handler for a specific endpoint. An endpoint is defined by the HTTP request method (GET in this case) and the route path. The route path of a handler combines the (optional) prefix declared for the controller **and** any path specified in the method's decorator. Since the example sets a prefix (`cats`) and no path in the method decorator, Nest maps `GET /cats` requests to this handler.
>
> If the method decorator also specified a path, such as `@Get('breed')`, the resulting route would be `GET /cats/breed`.
>
> When a `GET /cats` request arrives, Nest routes it to the user-defined `findAll()` method. The method name is arbitrary: you must declare a method to bind the route to, but Nest attaches no significance to its name.
>
> This method returns a 200 status code along with the associated response, which in this case is a string. To explain why, we need to introduce the two **different** options Nest provides for manipulating responses:
>
> **Standard (recommended)** — With this built-in method, when a route handler returns a JavaScript object or array, it is **automatically** serialized to JSON. When it returns a JavaScript primitive type (e.g., `string`, `number`, `boolean`), Nest sends the value without attempting to serialize it. Response handling is therefore straightforward: return the value, and Nest takes care of the rest.
>
> The response's **status code** is 200 by default, except for POST requests, which use 201. You can change this behavior by adding the `@HttpCode(...)` decorator at the handler level (see [Status code](https://docs.nestjs.com/controllers#status-code)).
>
> **Library-specific** — You can use the library-specific (e.g., Express) [response object](https://expressjs.com/en/api.html#res), injected with the `@Res()` decorator in the route handler signature (e.g., `findAll(@Res() response)`). This approach lets you use the native response handling methods exposed by that object. For example, with Express, you can construct responses with code like `response.status(200).send()`.
>
> **Warning** Nest detects when a handler uses either `@Res()` or `@Next()`, which indicates that you have chosen the library-specific option. If both approaches are used at the same time, the standard approach is **automatically disabled** for that route and no longer works as expected. To combine them (for example, to inject the response object only to set cookies or headers while leaving the rest to the framework), set the `passthrough` option to `true` in the `@Res({ passthrough: true })` decorator.

## 原文内容讲解

### 控制器前缀与路由方法

`@Controller('cats')` 给控制器下的路由添加共同前缀，`@Get()`、`@Post()` 等方法装饰器声明 HTTP 方法及可选路径。两者组合出最终端点，例如 `@Controller('cats')` 加 `@Get('breed')` 对应 `GET /cats/breed`。Nest 根据请求方法和路径找到处理方法；处理方法的名称只是普通方法名，不参与路由匹配。

### 标准响应

标准模式下，控制器只需返回结果，由 Nest 负责发送响应。对象和数组会序列化为 JSON；字符串、数字、布尔值等基本类型则直接作为响应内容发送。默认 GET 响应状态码为 200，POST 为 201；需要其他状态码时，可在处理方法上使用 `@HttpCode(...)`。

### 原生响应

使用 `@Res()` 后，控制器拿到的是 Express 等底层平台的原生 Response，可以直接调用平台方法发送响应。此时控制器负责完成响应；如果只设置响应头、cookie 或状态码，而仍希望 Nest 发送方法返回值，应使用 `@Res({ passthrough: true })`。

`@Next()` 也代表处理方法要参与底层平台的控制流程。若处理方法使用 `@Res()` 或 `@Next()`，Nest 不会再按标准模式自动发送返回值；应明确由控制器或 `next` 完成后续响应流程。

本文只跟踪官方 Routing 小节中的路由定义与响应方式。请求对象及从请求中提取参数的用例统一记录在 [Request object](./2.Request%20object.md)。

## 用例大纲

### 1. 声明控制器并注册路由

- ✅ `@Controller()` 标记控制器；Nest 启动时扫描控制器并注册路由。
- ✅ `@Controller('cats')` 路径前缀与 `@Get()` 方法路径组合成 `GET /cats`。
- ✅ 方法装饰器指定子路径，例如 `@Get('breed')` 与控制器前缀组合。
- ✅ 路由由 HTTP 方法和路径共同确定，并调用对应控制器方法。
- ✅ 控制器方法名由开发者定义，路由元数据绑定具体方法；方法名本身不参与 URL 匹配。
- ✅ `@Controller([...])` 与 `@Get([...])` 的路径组合；[path-arrays.e2e-spec.ts](../../test/1_controller/2_routing/path-arrays.e2e-spec.ts) 验证四个前缀/方法路径组合都可访问。
- 🟡 CLI 生成控制器是工具用法，不属于学习版运行时功能；尚未练习 `nest g controller`。

### 2. 标准响应方式

- ✅ 控制器返回对象时，由框架序列化为 JSON；[standard-responses.e2e-spec.ts](../../test/1_controller/2_routing/standard-responses.e2e-spec.ts) 已验证。
- ✅ 控制器返回数组时，由框架序列化为 JSON；[standard-responses.e2e-spec.ts](../../test/1_controller/2_routing/standard-responses.e2e-spec.ts) 已验证。
- ✅ 控制器返回字符串时，框架直接发送该值；[standard-responses.e2e-spec.ts](../../test/1_controller/2_routing/standard-responses.e2e-spec.ts) 已验证。
- ✅ 控制器返回数字时，框架直接发送该值；[standard-responses.e2e-spec.ts](../../test/1_controller/2_routing/standard-responses.e2e-spec.ts) 已验证。
- ✅ 默认状态码为 GET 200、POST 201；POST 201 已由 [param.e2e-spec.ts](../../test/1_controller/3_request-object/request-data/param.e2e-spec.ts) 验证。

### 3. 原生响应方式与 `@Next()`

- ✅ `@Res()` 注入 Express Response，由控制器调用原生 `send()` 发送响应；[native-responses.e2e-spec.ts](../../test/1_controller/2_routing/native-responses.e2e-spec.ts) 已验证。
- ✅ `@Response()` 作为 `@Res()` 别名；[native-responses.e2e-spec.ts](../../test/1_controller/2_routing/native-responses.e2e-spec.ts) 已验证可注入原生响应并发送响应体。
- ✅ 使用非 passthrough 的 `@Res()` 时，框架不再发送控制器返回值；[native-responses.e2e-spec.ts](../../test/1_controller/2_routing/native-responses.e2e-spec.ts) 已验证。
- ✅ `@Next()` 注入 Express 的 `next`，并可用 `next('route')` 跳过当前路由；[next.e2e-spec.ts](../../test/1_controller/2_routing/next.e2e-spec.ts) 已验证。
- ✅ `@Next()` 将错误传给 Express 错误处理中间件；[next.e2e-spec.ts](../../test/1_controller/2_routing/next.e2e-spec.ts) 已验证请求得到 500 响应。
- ✅ `@Res({ passthrough: true })` 允许设置响应状态和响应头，同时由框架发送方法返回值；[native-responses.e2e-spec.ts](../../test/1_controller/2_routing/native-responses.e2e-spec.ts) 已验证。
