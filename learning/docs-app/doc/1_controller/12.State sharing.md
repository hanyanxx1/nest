# State sharing：学习锚点与进度

官方章节：[Controllers - State sharing](https://docs.nestjs.com/controllers#state-sharing)

## 官方内容依据

以下内容依据你粘贴的官方原文：Nest 的资源和单例服务通常会跨请求共享；Node.js 不采用每个请求由独立线程处理的多线程无状态模型，因此在 Nest 中使用单例实例是安全的。少数场景可能需要按请求创建控制器实例，例如 GraphQL 的请求级缓存、请求跟踪或多租户；具体生命周期控制见 [Injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes)。

## 用例与进度

- ✅ `state-sharing.e2e-spec.ts` 验证同一应用连续请求两次时，控制器计数依次返回 `1`、`2`。
- ✅ 已沿 `NestFactory` 创建控制器、`NestApplication.init()` 注册路由、请求处理函数调用控制器方法的主干追踪实现。
- 请求作用域的依赖注入及其生命周期不在本标题实现；这里只确认当前学习版的共享实例行为，并记录该边界。

## 学习版实现线索

- `NestFactory.create()` 为每个应用实例创建 provider 实例；控制器实例在应用初始化注册路由时创建。
- `NestApplication.init()` 只执行一次路由注册；已注册的处理函数持有对应的控制器实例，并在每次请求时调用它的方法。
- 因此共享范围是单个应用实例内的请求，不应理解为跨多个应用实例共享同一个对象。
