# Status code：学习锚点与进度

官方章节：[Controllers - Status code](https://docs.nestjs.com/controllers#status-code)

## 官方内容依据

以下内容依据你粘贴的官方原文：默认响应状态码为 `200`，`POST` 默认使用 `201`；可以在处理方法上使用 `@HttpCode(...)` 覆盖。状态码需要根据情况动态决定时，可以使用平台原生响应对象，或在错误场景中抛出异常。

## 当前学习版实现

- `@HttpCode(statusCode)` 将状态码写入处理方法的 `HTTP_CODE_METADATA` 元数据。
- `RouterExplorer` 执行处理方法后读取该元数据；没有显式状态码时，`POST` 使用 `201`，其他方法将未指定的状态码交给 Express 处理。
- `RouterResponseController` 将状态码传给 Express adapter。`@Res({ passthrough: true })` 动态设置状态码的路径已在 Routing 用例中验证。
- 学习版目前没有异常过滤器；通过抛异常动态返回状态码的路径暂缓到异常处理主题。

## 用例与进度

- ✅ 默认 GET `200`、POST `201` 已由现有路由与请求数据测试验证。
- ✅ `@HttpCode(202)` 覆盖 POST 默认状态码已由 `standard-responses.e2e-spec.ts` 验证。
- ✅ 本标题新增代表性用例：`POST /cats` 使用 `@HttpCode(204)` 覆盖默认 `201`，见 `status-code.e2e-spec.ts`。
- ✅ 使用 passthrough `@Res()` 设置状态码已由 `native-responses.e2e-spec.ts` 验证。
- ➖ 异常驱动的动态状态码暂缓，原因是学习版尚未实现异常过滤器。
