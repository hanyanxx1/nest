# Request object：学习用例大纲与进度

官方章节：[Controllers - Request object](https://docs.nestjs.com/controllers#request-object)

## 官方原文（学习依据）

以下原文以本次学习时对照的官方文档内容为依据：

> Handlers often need access to the client's **request** details. Nest provides access to the [request object](https://expressjs.com/en/api.html#req) of the underlying platform (Express by default). To access it, add the `@Req()` decorator to the handler's signature, which instructs Nest to inject it.
>
> ```typescript
> import { Controller, Get, Req } from '@nestjs/common';
> import type { Request } from 'express';
>
> @Controller('cats')
> export class CatsController {
>   @Get()
>   findAll(@Req() request: Request): string {
>     return 'This action returns all cats';
>   }
> }
> ```
>
> **Hint** To take advantage of `express` typings (as in the `request: Request` parameter above), install the `@types/express` package.
>
> The request object represents the HTTP request and has properties for the query string, route parameters, HTTP headers, and body (see the [Express documentation](https://expressjs.com/en/api.html#req)). In most cases, you don't need to access these properties manually. Instead, use dedicated decorators such as `@Body()` or `@Query()`, which are available out of the box. The following table lists the provided decorators and the platform-specific objects they represent.
>
> | Decorator | Request/response value |
> |---|---|
> | `@Request(), @Req()` | `req` |
> | `@Response(), @Res()` | `res` |
> | `@Next()` | `next` |
> | `@Session()` | `req.session` |
> | `@Param(key?: string)` | `req.params` / `req.params[key]` |
> | `@Body(key?: string)` | `req.body` / `req.body[key]` |
> | `@Query(key?: string)` | `req.query` / `req.query[key]` |
> | `@Headers(name?: string)` | `req.headers` / `req.headers[name]` |
> | `@Cookies(name?: string)` | request cookies / the cookie named `name` |
> | `@SignedCookies(name?: string)` | verified signed cookies / the signed cookie named `name` |
> | `@Ip()` | `req.ip` |
> | `@HostParam()` | `req.hosts` |
>
> For compatibility with typings across underlying HTTP platforms (e.g., Express and Fastify), Nest provides the `@Res()` and `@Response()` decorators. `@Res()` is an alias for `@Response()`. Both directly expose the native `response` object of the underlying platform. When using them, also install the typings for the underlying library (e.g., `@types/express`) to take full advantage of them. When you inject either `@Res()` or `@Response()` in a route handler, you put Nest into **library-specific mode** for that handler, and you become responsible for managing the response. You must then send a response by calling a method on the `response` object (e.g., `res.json(...)` or `res.send(...)`); otherwise, the request will hang.
>
> `@Body()`, `@Query()`, `@Param()`, and `@RawBody()` also accept an options object with `schema` and `pipes` properties. This lets you attach [Standard Schema](https://standardschema.dev/) compatible schemas, such as those created with Zod, Valibot, or ArkType, directly to route parameters.
>
> ```typescript
> @Post()
> create(@Body({ schema: createCatSchema }) createCatDto: CreateCatDto) {
>   return this.catsService.create(createCatDto);
> }
>
> @Get(':id')
> findOne(@Param('id', { schema: z.coerce.number().int().positive() }) id: number) {
>   return this.catsService.findOne(id);
> }
> ```
>
> On their own, these decorators only attach the schema as metadata. To validate against it, register the built-in `StandardSchemaValidationPipe` or a custom pipe that reads `metadata.schema`.
>
> **Hint** To learn how to create your own decorators, see the [Custom route decorators](https://docs.nestjs.com/custom-decorators) chapter.

## 原文内容讲解

### 请求对象与专用参数装饰器

Nest 会把底层 HTTP 平台的请求对象注入 `@Req()` 参数。请求对象包含路径参数、查询参数、请求头和请求体等信息；一般不必手动从整个对象中取值，可以使用更明确的装饰器，例如 `@Param()`、`@Query()`、`@Body()` 和 `@Headers()`。有 key 时取指定字段，无 key 时取对应的完整对象。

### 请求上下文装饰器

`@Request()` 是 `@Req()` 的别名；`@Response()` 与 `@Res()` 对应底层响应对象；`@Next()` 注入 Express 的后续流程回调。`@Session()`、`@Cookies()` 和 `@SignedCookies()` 分别读取会话、普通 Cookie 和已验证签名的 Cookie。`@Ip()` 读取客户端 IP，`@HostParam()` 读取 Host 路由匹配过程中提取的域名参数。

其中 `@Res()` / `@Response()` 直接暴露平台响应对象，使用时需要自行发送响应。该行为与标准响应模式的关系及 passthrough 用法见 [Routing](./2.Routing.md)。

### 参数装饰器上的 schema 与 pipes

`@Body()`、`@Query()`、`@Param()` 和 `@RawBody()` 可以通过 options 附加 schema 和 pipes 配置。装饰器负责把配置记入元数据，本身不会执行校验；请求进入处理流程后，需要注册 `StandardSchemaValidationPipe` 或自定义 pipe，读取 schema 并验证参数。schema 也可以转换输入值，转换后的值可交给控制器方法。

### 自定义参数装饰器

官方在本节末尾链接到自定义路由装饰器，提示开发者可以创建自己的参数装饰器。它是后续主题的入口，不是本节请求对象装饰器清单中的内置项。

本文按官方小节整理请求对象及请求数据提取相关的用例。路由声明、响应模式、`@Res()` / `@Next()` 对标准响应的影响归入 [Routing](./2.Routing.md)，此处只跟踪从请求对象读取数据的行为。

### 3. 请求体、查询参数和路由参数上的 schema / pipes

- ⬜ `@Body({ schema })` 将 schema 附加到参数元数据。
- ⬜ `@Query({ schema })` 将 schema 附加到参数元数据。
- ⬜ `@Param(name, { schema })` 将 schema 附加到参数元数据。
- ⬜ `@RawBody({ schema })` 支持 schema 元数据，并能提供未解析的原始请求体。
- ⬜ 上述参数装饰器支持 `pipes` 选项。
- ⬜ 单独添加管道后，验证 schema 被执行；装饰器自身只记录元数据，不负责校验。
- ⬜ Standard Schema 校验成功时，将 schema 产生的值传给控制器。
- ⬜ 覆盖校验失败时的 HTTP 错误响应。
- ⬜ 覆盖异步 schema 校验。

这是本节尚未开始的主要部分。按小步流程，先验证 schema 元数据如何附加，再验证注册的 `StandardSchemaValidationPipe` 如何读取并执行它；不预先实现完整 pipes 系统。
