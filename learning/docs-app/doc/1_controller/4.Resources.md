## 官方内容依据

以下内容以你粘贴的官方原文为依据。保留一句关键短引文，其余内容用中文概括：

> “Typically, we also want an endpoint that creates new records.”

官方示例在 `cats` 控制器中为同一路径定义 `POST` 和 `GET` 处理器：`POST` 用于创建记录，`GET` 用于获取资源。示例返回字符串来表示不同操作，并未实现真实数据库读写。

原文还列出 `@Get()`、`@Post()`、`@Put()`、`@Delete()`、`@Patch()`、`@Options()`、`@Head()`、`@QueryMethod()` 等 HTTP 方法装饰器，并说明 `@All()` 可处理所有这些方法。`@QueryMethod()` 映射 HTTP `QUERY`，使用这个名称是为了与读取 URL 查询参数的 `@Query()` 装饰器区分。

## 与当前学习实现的关系

学习版已经定义了这些方法装饰器及对应的 `RequestMethod` 枚举；目前路由注册已支持 `GET`、`POST`、`PUT`、`DELETE`、`PATCH`、`OPTIONS`、`HEAD`、`QUERY` 和 `ALL`。本节将验证方法装饰器声明的 HTTP 方法是否真正注册并分发到对应控制器方法，再逐步补齐缺失的路由行为。

本节聚焦资源路由和 HTTP 方法映射。路由通配符、冲突及解析顺序分别属于后续官方小节，不在此处提前实现。

## 用例大纲

### 1. 资源控制器的 GET 与 POST

- ✅ 用 `GET /cats` 获取资源、`POST /cats` 创建资源；同一路径的两种 HTTP 方法分别命中对应处理器（`resources.e2e-spec.ts`）。

### 2. 标准 HTTP 方法装饰器

- ✅ `@Put()` 注册并处理 `PUT /cats`（`resources.e2e-spec.ts`）。
- ✅ `@Delete()` 注册并处理 `DELETE /cats`（`resources.e2e-spec.ts`）。
- ✅ `@Patch()` 注册并处理 `PATCH /cats`（`resources.e2e-spec.ts`）。
- ✅ `@Options()` 注册并处理 `OPTIONS /cats`（`resources.e2e-spec.ts`）。
- ✅ `@Head()` 注册并处理 `HEAD /cats`；通过处理器调用次数验证（`resources.e2e-spec.ts`）。
- ✅ `@QueryMethod()` 注册并处理真实 HTTP `QUERY` 请求（`resources.e2e-spec.ts`）；URL 查询参数由参数装饰器 `@Query()` 处理，参见 Request object 用例。
- ✅ `@All()` 让 GET、POST、DELETE 请求命中同一处理器（`resources.e2e-spec.ts`）。
