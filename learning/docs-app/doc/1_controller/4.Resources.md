# Resources：学习用例大纲与进度

官方章节：[Controllers - Resources](https://docs.nestjs.com/controllers#resources)

## 官方内容依据

以下内容以你粘贴的官方原文为依据。保留一句关键短引文，其余内容用中文概括：

> “Typically, we also want an endpoint that creates new records.”

官方示例在 `cats` 控制器中为同一路径定义 `POST` 和 `GET` 处理器：`POST` 用于创建记录，`GET` 用于获取资源。示例返回字符串来表示不同操作，并未实现真实数据库读写。

原文还列出 `@Get()`、`@Post()`、`@Put()`、`@Delete()`、`@Patch()`、`@Options()`、`@Head()`、`@QueryMethod()` 等 HTTP 方法装饰器，并说明 `@All()` 可处理所有这些方法。`@QueryMethod()` 映射 HTTP `QUERY`，使用这个名称是为了与读取 URL 查询参数的 `@Query()` 装饰器区分。

## 与当前学习实现的关系

学习版已经定义了这些方法装饰器及对应的 `RequestMethod` 枚举，但路由注册目前只连接了 `GET` 与 `POST`。本节将验证方法装饰器声明的 HTTP 方法是否真正注册并分发到对应控制器方法，再逐步补齐缺失的路由行为。

本节聚焦资源路由和 HTTP 方法映射。路由通配符、冲突及解析顺序分别属于后续官方小节，不在此处提前实现。

## 用例大纲

### 1. 资源控制器的 GET 与 POST

- 🟡 学习版已有 GET/POST 路由及响应测试；尚未用一个资源示例验证同一路径按 HTTP 方法分发到不同处理器。
- ⬜ 用 `GET /cats` 获取资源、`POST /cats` 创建资源，验证两种请求命中各自的处理器并返回对应结果。

### 2. 标准 HTTP 方法装饰器

- 🟡 `@Put()`、`@Delete()`、`@Patch()`、`@Options()`、`@Head()`、`@QueryMethod()`、`@All()` 已有装饰器定义；当前路由注册器尚未支持这些方法。
- ⬜ 验证 `PUT`、`DELETE`、`PATCH`、`OPTIONS`、`HEAD` 分别注册并分发到对应控制器方法。
- ⬜ 验证 `@QueryMethod()` 处理 HTTP `QUERY` 请求，并与参数装饰器 `@Query()` 区分。
- ⬜ 验证 `@All()` 能接收不同 HTTP 方法的请求。

## 验证方式
