# Services：学习锚点与进度

官方章节：[Providers - Services](https://docs.nestjs.com/providers#services)

## 官方内容讲解

官方用 `CatsService` 封装猫数据的保存和读取：`create()` 将数据加入服务内部的数组，`findAll()` 返回数组。服务是普通类，通过 `@Injectable()` 声明可由 Nest IoC 容器管理。

`CatsController` 通过构造函数接收 `CatsService`，再把创建和查询操作委托给服务。官方同时展示了 CLI 生成服务的命令；该命令属于样板生成工具，不是运行时机制。

## 当前实现与已有用例

- [provider-injection.e2e-spec.ts](../../test/2_Providers/1_providers/provider-injection.e2e-spec.ts) 已通过：模块登记 `CatsService` 后，控制器能调用注入的服务并返回 `['Milo']`。
- [Injectable 装饰器](../../@nest/common/decorators/core/injectable.decorator.ts) 会向类写入 `INJECTABLE_WATERMARK` 元数据。
- [NestFactory](../../@nest/core/nest-factory.ts) 当前根据模块 `providers` 数组创建服务实例，并按控制器构造函数的类型元数据注入依赖；这条流程没有读取 `INJECTABLE_WATERMARK`。
- [state-sharing.e2e-spec.ts](../../test/1_controller/12_state_sharing/state-sharing.e2e-spec.ts) 已验证单个应用中的控制器实例会在连续请求间保留状态；它没有验证 `CatsService` 的 `create()` / `findAll()` 数据流。

## 服务数据流验证

- ✅ [cats-service.e2e-spec.ts](../../test/2_Providers/2_services/cats-service.e2e-spec.ts) 已通过：`POST /cats` 写入 `{ name: 'Milo', age: 3, breed: 'Maine Coon' }` 后，`GET /cats` 返回这只猫。
- 该用例验证了控制器将两个请求委托给同一个注入的服务实例；服务把 POST 收到的数据加入内部数组，后续 GET 再读取该数组。

本用例不验证容器是否依赖 `@Injectable()` 标记才允许注册服务；当前学习版的 Provider 注册代码尚未读取该标记。
