# Optional providers：学习锚点与进度

官方章节：[Providers - Optional providers](https://docs.nestjs.com/providers#optional-providers)

## 官方内容讲解

并非所有依赖都是必需的。构造函数参数加上 `@Optional()` 后，如果容器中没有对应 Provider，注入值应为 `undefined`，应用不应因此在启动时失败；类可以自行使用默认值。

官方示例同时使用 `@Inject('HTTP_OPTIONS')` 传入自定义字符串 token。该 token 的注册和查找依赖 Custom providers，本小节的核心行为则是缺少可选依赖时不报错并传入 `undefined`。

## 学习版现状与已有用例

- 学习版的 `@Optional()` 将可选参数的位置写入 `OPTIONAL_DEPS_METADATA`。
- [NestFactory](../../@nest/core/nest-factory.ts) 读取可选参数索引；Provider 缺失且参数被标记为可选时，向构造函数传入 `undefined`，否则仍抛出缺失依赖错误。
- `ModuleMetadata.providers` 目前只接受类数组；本节官方示例中的字符串 token 不在当前支持范围内。

## 验证结果

- ✅ [optional-provider.e2e-spec.ts](../../test/2_Providers/6_optional_providers/optional-provider.e2e-spec.ts) 已通过：未登记的 `CatsService` 被标记为可选依赖；应用初始化成功，控制器收到 `undefined` 并返回 `['fallback']`。
- ✅ 回归测试通过： [interface-injection.e2e-spec.ts](../../test/2_Providers/3_dependency_injection/interface-injection.e2e-spec.ts) 确认未标记为可选的 interface 依赖仍会因 `Object` token 未登记而失败；[provider-injection.e2e-spec.ts](../../test/2_Providers/1_providers/provider-injection.e2e-spec.ts) 确认已登记的 class Provider 仍可正常注入。
- 本用例验证可选依赖的缺失处理，不涉及自定义 token；`@Inject('HTTP_OPTIONS')` 留待 Custom providers 指南。
