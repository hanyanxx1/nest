# Scopes：学习锚点与进度

官方章节：[Providers - Scopes](https://docs.nestjs.com/providers#scopes)

## 官方内容讲解

默认情况下，Provider 的生命周期与应用相同：应用启动时创建 Provider，应用关闭时销毁 Provider。也可以改用其他作用域，例如让 request-scoped Provider 的生命周期跟随单个请求；具体用法由官方 Injection scopes 章节展开。

## 学习版现状与已有证据

- [NestFactory](../../@nest/core/nest-factory.ts) 在每次 `create()` 时为模块中登记的每个 Provider 创建一个实例，并将实例 Map 保存在该应用的路由注册闭包中；同一应用中的多个消费者复用该实例。
- ✅ [provider-singleton-sharing.e2e-spec.ts](../../test/2_Providers/3_dependency_injection/provider-singleton-sharing.e2e-spec.ts) 已通过：同一应用中的两个控制器通过同一 Provider 共享数据。
- [NestApplication.close()](../../@nest/core/nest-application.ts) 当前只关闭 HTTP server；学习版没有 Provider 销毁钩子或应用关闭生命周期处理。
- 学习版没有 request-scoped Provider 或按请求创建依赖的机制。

## 应用实例隔离验证

- ✅ [provider-application-scope.e2e-spec.ts](../../test/2_Providers/4_scopes/provider-application-scope.e2e-spec.ts) 已通过：第一个应用通过 POST 写入 Milo 后，第二个独立应用的 GET 仍返回空数组。
- 该结果验证每次 `NestFactory.create()` 都创建独立的 Provider 实例和状态；同一个应用内的多个消费者仍共享该应用自己的实例。

Provider 销毁钩子需要应用关闭生命周期机制；request scope 则需要按请求解析依赖。两者不在当前最小 DI 实现中，先记录为后续相关主题的范围，不在本步预先扩展。
