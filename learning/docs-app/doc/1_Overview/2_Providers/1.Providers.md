# Providers：章节概述

官方章节：[Providers](https://docs.nestjs.com/providers)

## 官方内容讲解

Provider 是 Nest 组织对象关系的基础概念。Service、repository、factory 和 helper 等类都可以作为 provider；对象将 provider 声明为依赖后，由 Nest runtime 创建并连接这些对象。

Controller 负责处理 HTTP 请求，并把较复杂的工作委托给 provider。最简单的 provider 是普通 JavaScript 类，登记在模块 `@Module()` 的 `providers` 数组中。官方提示可继续阅读 Modules 章节了解模块细节，并建议用 SOLID 原则组织依赖。

## 学习版现状

- [NestFactory](../../@nest/core/nest-factory.ts) 会读取根模块的 `providers`，创建 provider 实例并按类保存。
- 创建控制器时，学习版读取控制器构造函数的 `design:paramtypes`，再从 provider 实例表中取出对应依赖并传入控制器。
- 当前实现覆盖了最基本的“模块注册 provider，并注入控制器”路径；provider 自身的递归依赖解析、模块 `imports` 等机制不在此处现有实现范围内。

## 本节验证目标

此用例对应官方关于控制器委托复杂工作、provider 作为依赖注入的说明。

- ✅ [provider-injection.e2e-spec.ts](../../test/2_Providers/1_providers/provider-injection.e2e-spec.ts) 已通过：`CatsService` 登记在模块的 `providers` 中并注入 `CatsController`；请求 `GET /cats` 得到服务返回的 `['Milo']`。
- 本用例验证了基础路径：模块登记 provider → 创建 provider 实例 → 按控制器构造函数类型注入 → 控制器委托给服务并返回结果。
