# Dynamic modules：学习锚点与进度

官方章节：[Modules - Dynamic modules](https://docs.nestjs.com/modules#dynamic-modules)

## 当前学习步骤

动态模块工厂方法（例如 `forRoot()`）返回一个 `DynamicModule` 对象。对象中的 `module` 指向实际的模块类，其他字段用于补充该模块的元数据。

当前用例验证静态 `@Module()` 元数据与动态对象的类元数据合并到同一个模块上下文：

1. `AppModule` 的 `imports` 中读取到 `FeatureFlagsModule.forRoot()` 返回的动态对象。
2. `visit()` 保留该对象为 `dynamicMetadata`，并通过 `getModuleType()` 取出 `FeatureFlagsModule` 类。
3. `mergeClassMetadata()` 将类上的静态元数据与动态对象中的 `controllers`、`providers`、`exports` 分别合并。
4. Provider 创建流程实例化合并后的 Provider，并按类型存入模块的 Provider Map；导出列表使消费者能够解析这些实例。

## 用例与验证

- [dynamic-module-metadata.e2e-spec.ts](../../../test/1_Overview/3_Modules/7_Dynamic%20modules/dynamic-module-metadata.e2e-spec.ts)：验证静态 `StaticFlagsService` 与动态追加的 `RuntimeFlagsService` 都能注入，并由 HTTP 响应确认调用结果。用户报告 1 个测试通过。

## 当前实现边界

- 已实现并验证：同步动态模块对象中的类 Provider 元数据与静态模块元数据合并。
- 尚未实现：动态对象自身的 `imports` 递归收集；`useValue` 等自定义 Provider 与非类 token；构造函数显式 token 注入；动态模块的全局与异步配置。
- 当前测试只覆盖一个动态配置实例，尚未验证同一模块类以不同配置重复导入的行为。
