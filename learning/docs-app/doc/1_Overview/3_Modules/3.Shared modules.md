# Shared modules：学习锚点与进度

官方章节：[Modules - Shared modules](https://docs.nestjs.com/modules#shared-modules)

## 官方内容讲解

模块默认是单例边界。模块把 Provider 放在自己的 `providers` 中，并用 `exports` 明确公开；其他模块通过 `imports` 引入后，可以注入提供模块创建的同一个 Provider 实例。

如果每个消费者模块都把同一个 Service 类分别登记到自己的 `providers`，它们会创建不同实例，状态不会共享。共享模块把 Provider 的创建和状态集中在一处。

## 学习版现状与已有用例

- [`ModuleMetadata`](../../../@nest/common/interfaces/modules/module-metadata.interface.ts) 已加入 `exports?: Function[]`。
- [`NestFactory`](../../../@nest/core/nest-factory.ts) 将模块导出清单保存到 `ModuleContext`；Controller 构造函数、Controller 属性和 Provider 属性依赖均通过同一查找逻辑解析：先查本模块 Provider Map，再查直接导入且导出了目标 Provider 的模块。
- [shared-module.e2e-spec.ts](../../../test/1_Overview/3_Modules/3_Shared%20modules/shared-module.e2e-spec.ts) 中，两个消费者模块都只 `imports: [SharedCounterModule]`，没有在各自 `providers` 重复登记 `SharedCounterService`。测试通过：A 请求返回计数 `1`，B 请求返回 `2`，验证两者拿到同一个 Service 实例。
- [shared-module-property-injection.e2e-spec.ts](../../../test/1_Overview/3_Modules/3_Shared%20modules/shared-module-property-injection.e2e-spec.ts) 验证两个消费者 Controller 通过 `@Inject()` 属性注入取得同一个导出实例；测试通过，计数依次为 `1`、`2`。

## 已验证范围

- 已验证：模块显式 `exports` Provider 后，直接导入该模块的两个消费者，其 Controller 构造函数可以注入它，并共享同一实例。
- 已验证：两个消费者 Controller 通过属性注入共享导出的 Provider 实例。
- 已接入但尚未单独验证：Provider 属性注入从直接导入并导出目标 Provider 的模块中解析依赖。
- 尚未实现或验证：模块重导出、导出项在模块扫描阶段的提前校验，以及其他 Provider token 类型。
