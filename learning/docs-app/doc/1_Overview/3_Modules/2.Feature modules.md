# Feature modules：学习锚点与进度

官方章节：[Modules - Feature modules](https://docs.nestjs.com/modules#feature-modules)

## 官方内容讲解

Feature module 把同一业务能力中的 Controller 和 Provider 放在一个模块中，形成清楚的组织边界。应用根模块通过 `imports` 引入 feature module，由 Nest 从根模块继续发现并组织应用结构。

## 学习版现状与已有用例

- [`ModuleMetadata`](../../../@nest/common/interfaces/modules/module-metadata.interface.ts) 已声明 `imports?: Function[]`；[`@Module()`](../../../@nest/common/decorators/modules/module.decorator.ts) 会保存传入的 `imports` 元数据。
- [`NestFactory`](../../../@nest/core/nest-factory.ts) 会递归遍历 `imports`，为每个模块分别创建 Provider Map，并从已发现的模块收集 Controller。
- [feature-module.e2e-spec.ts](../../../test/1_Overview/3_Modules/2_Feature%20modules/feature-module.e2e-spec.ts) 覆盖单层导入、三层嵌套导入，以及根/中间/叶子模块各自的 Controller 和 Provider；最新结果为 3 个测试全部通过。
- [provider-injection.e2e-spec.ts](../../../test/1_Overview/2_Providers/1_providers/provider-injection.e2e-spec.ts) 覆盖 Controller 与 Provider 登记在同一个模块的情况；回归测试通过（1 个测试）。

## 已验证的第一个行为

定义 `CatsModule`，在其中登记 `CatsController` 和 `CatsService`；根 `AppModule` 仅通过 `imports: [CatsModule]` 引入它。启动根模块后请求 `/cats`，得到 `['Milo']`，对应测试已通过。该行为验证了根模块的 `imports` 是否参与应用模块发现；`exports` 和跨模块 Provider 注入尚未在本学习单元实现或验证。

## 已确认的边界与后续

- 真实 NestJS 中，导入模块不会自动暴露它的所有 Provider。要让消费者模块注入某个 Provider，通常由提供者模块通过 `exports` 暴露它，再由消费者模块 `imports` 该模块。
- 如果消费者模块把同一个 Service 类再次写入自己的 `providers`，它会在消费者模块中注册自己的实例；这不是复用提供者模块的实例。
- Feature modules 小节的实现范围是递归发现导入模块及其 Controller/Provider；跨模块 Provider 的 `exports` 共享属于后续 Shared modules 小节，已在对应进度文档中继续实现和验证。
