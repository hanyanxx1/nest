# Modules：学习锚点与进度

官方章节：[Modules](https://docs.nestjs.com/modules)

## 官方内容讲解

`@Module()` 用元数据描述应用结构。每个 Nest 应用至少有一个根模块，Nest 从根模块开始组织应用中的模块、Controller 和 Provider。

模块元数据包含：

- `providers`：由 Nest 创建、可在模块范围内注入的 Provider。
- `controllers`：由该模块管理的 Controller。
- `imports`：当前模块依赖的其他模块。
- `exports`：向导入当前模块的其他模块公开的 Provider，构成模块的公共接口。

模块默认封装自己的 Provider；其他模块不能直接注入它们，除非该 Provider 被导出并通过模块关系引入。

## 学习版现状与已有用例

- [`@Module()`](../../../@nest/common/decorators/modules/module.decorator.ts) 把传入的元数据逐项写入类的 Reflect metadata。
- [`ModuleMetadata`](../../../@nest/common/interfaces/modules/module-metadata.interface.ts) 目前声明了 `imports`、`controllers`、`providers`，尚未声明 `exports`。
- [`NestFactory`](../../../@nest/core/nest-factory.ts) 把传入的模块类作为根模块，只读取它的 `controllers` 和 `providers`；目前不遍历 `imports`、不处理 `exports`，也没有模块间 Provider 可见性规则。
- [provider-injection.e2e-spec.ts](../../../test/1_Overview/2_Providers/1_providers/provider-injection.e2e-spec.ts) 已验证根模块登记 `CatsService` 并将其注入 `CatsController`。用户此前报告该测试通过，因此本标题复用这份证据，不新增等价测试。

## 当前范围

本标题先建立模块元数据和根模块的概念基线。Feature modules、Shared modules、模块导出与封装等行为，需结合后续官方小节逐项学习和验证；当前实现尚不支持模块图。
