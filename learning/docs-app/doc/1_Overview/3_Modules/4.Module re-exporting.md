# Module re-exporting：学习锚点与进度

官方章节：[Modules - Module re-exporting](https://docs.nestjs.com/modules#module-re-exporting)

## 官方内容讲解

模块除了导出自己的 Provider，也可以把自己导入的模块再导出。这样，下游模块只需导入这个转发模块，就能使用被转发模块公开的 Provider。

本节的关系是：`CommonModule` 创建并导出 `CommonService`；`CoreModule` 导入并再导出 `CommonModule`；`AppModule` 只导入 `CoreModule`，仍能注入 `CommonService`。

## 学习版现状与用例

- [`ModuleMetadata`](../../../@nest/common/interfaces/modules/module-metadata.interface.ts) 的 `exports` 使用 `Function[]`，因此既能保存 Provider 类，也能保存模块类。
- [`collectModuleContexts()`](../../../@nest/core/nest-factory.ts) 会递归收集 `imports` 中的模块；[`resolveProvider()`](../../../@nest/core/nest-factory.ts) 通过 [`findExportedProvider()`](../../../@nest/core/nest-factory.ts) 沿模块明确声明的再导出关系查找 Provider，并从声明该 Provider 的模块 Map 取出已有实例。
- [module-re-export.e2e-spec.ts](../../../test/1_Overview/3_Modules/4_Module%20re-exporting/module-re-export.e2e-spec.ts) 验证 `AppModule → CoreModule → CommonModule` 的依赖链；`GET /common` 返回 `{ source: 'CommonModule' }`。用户报告该测试通过（1 个测试）。

## 已验证范围与边界

- 已验证一层模块再导出：`CoreModule` 导出其导入的 `CommonModule`，根模块经由 `CoreModule` 注入 `CommonService`。
- 查找代码可继续沿着显式再导出的模块递归，并使用已访问集合避免循环；更深层的再导出链尚未单独测试。
- 尚未实现或验证：无效导出声明的提前校验，以及非类 Provider token。
