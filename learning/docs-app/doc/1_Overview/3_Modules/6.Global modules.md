# Global modules：学习锚点与进度

官方章节：[Modules - Global modules](https://docs.nestjs.com/modules#global-modules)

## 官方内容讲解

Nest 默认把 Provider 限定在模块作用域内；消费者通常要导入 Provider 所属模块，才能使用它导出的 Provider。用 `@Global()` 标记模块后，该模块只需在应用模块图中注册一次（通常放在根模块或 CoreModule），其导出的 Provider 就能被其他模块使用，而不必由每个消费者重复声明 `imports`。

全局模块减少了重复导入，但不应因此把所有模块都设为全局。显式 `imports` 能清楚表达模块依赖，并保留模块的公共 API 边界，减少无关模块之间的耦合。

## 学习版现状与用例

- [`@Global()`](../../../@nest/common/decorators/modules/global.decorator.ts) 在模块类上写入 `GLOBAL_MODULE_METADATA` 标记。
- [`collectModuleContexts()`](../../../@nest/core/nest-factory.ts) 先从根模块沿显式 `imports` 收集当前应用的模块，再把已收集的全局模块绑定进其他模块上下文的 `importedModuleTypes`。全局模块自身不会导入自己，已有的显式导入也不会重复追加。
- Provider 查找仍复用 [`resolveProvider()`](../../../@nest/core/nest-factory.ts) 和 [`findExportedProvider()`](../../../@nest/core/nest-factory.ts)：全局模块提供可见性，但目标 Provider 仍必须出现在它的 `exports` 中。
- [global-module.e2e-spec.ts](../../../test/1_Overview/3_Modules/6_Global%20modules/global-module.e2e-spec.ts) 验证 `AppModule` 注册 `GlobalCatsModule`，`ConsumerModule` 不导入它，但 `ConsumerController` 仍能注入导出的 `CatsService`。用户报告该测试通过（1 个测试）。

## 已验证范围与边界

- 已验证一个全局模块由根模块导入一次后，可向未显式导入它的消费者提供其导出的 Provider。
- 全局模块仍遵守 `exports` 边界；本用例验证了导出的 Provider 可注入，未另设“未导出的 Provider 不可注入”测试。该规则由现有 `findExportedProvider()` 路径执行。
- 当前收集范围是从根模块通过显式 `imports` 可达的模块；未被纳入应用模块图的 `@Global()` 类不会被发现。
- 官方建议避免过度使用全局模块，优先使用显式 `imports` 表达依赖。
