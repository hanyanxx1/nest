# Observing routes in production：学习锚点与进度

官方章节：[Controllers - Observing routes in production](https://docs.nestjs.com/controllers#observing-routes-in-production)

## 官方内容依据

以下内容依据你粘贴的官方原文：生产环境应以声明的 route pattern 观察请求；NestJS Observe 通过 `@nestjs/observe` SDK 接入 Nest 请求生命周期，以 route pattern 标记测量结果，并可从 p95、单次执行 waterfall 等视图定位耗时位于 controller、service 或数据库。初始化需要设置 `instrument: ObserveInstrument`，并在根模块导入 `ObserveModule.forRoot()`；后续配置见 [Observability](https://docs.nestjs.com/observability/overview) 和 [Dashboard](https://docs.nestjs.com/observability/dashboard)。

## 当前学习版检查

- 学习版 `NestFactory.create()` 尚无 `instrument` 选项，`@nest/core` 未发现对应 instrumentation 生命周期；`@nestjs/observe` 也不在学习版依赖中。
- 官方 Nest 核心源码已有 `instrument.instanceDecorator` 接入 Injector 和应用实例/函数的装饰钩子；Observe SDK 则负责把这些生命周期信息用于生产观测。

## 范围与进度

- 本标题介绍生产观测产品的集成与使用，不属于 controller 请求处理的基础主干行为。
- 完整实现需要接入外部 Observe SDK 并扩展 NestFactory、依赖注入和多个实例/请求生命周期，属于大型机制。
- ⏸️ 用户决定暂缓 SDK 实现和核心 hook 学习；后续学习 Injector/生命周期时再回看 `instrument.instanceDecorator`。当前未新增测试或实现。
