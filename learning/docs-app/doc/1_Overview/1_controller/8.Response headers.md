# Response headers：学习锚点与进度

官方章节：[Controllers - Response headers](https://docs.nestjs.com/controllers#response-headers)

## 官方内容依据

以下内容依据你粘贴的官方原文：可以通过方法级 `@Header(name, value)` 装饰器设置响应头，也可以注入平台原生响应对象并调用其 header 方法。

## 当前学习版实现

- 原生 Express Response 已可通过 `@Res()` 注入并设置响应头；相关行为已在 Routing 的 `native-responses.e2e-spec.ts` 中验证。
- `@Header(name, value)` 将 header 信息写入 `HEADERS_METADATA`；路由执行时由 `RouterExplorer` 读取，再经 `RouterResponseController` 委托给 Express adapter 设置到响应上。

## 用例与进度

- ✅ 原生响应对象设置 header 的方式已在 Routing 标题验证；本标题不重复该用例。
- ✅ 方法级 `@Header('Cache-Control', 'no-store')` 设置响应头，同时保留默认 POST 状态码 `201` 和标准响应体；`status-code.e2e-spec.ts` 的 1 项测试通过。

## 学习记录

- 测试先因 `Header is not a function` 失败，确认公共装饰器尚未实现或导出。
- 添加装饰器及其导出后，测试进一步因缺少 `Cache-Control` 响应头失败，确认运行时尚未读取并应用 header 元数据。
- 补齐路由执行、响应控制器与 Express adapter 的 header 传递后，用例通过。

相关文件：`@nest/common/decorators/http/`、`@nest/core/router/router-explorer.ts`、`@nest/platform-express/adapters/express-adapter.ts`。
