# Getting up and running：学习锚点与进度

官方章节：[Controllers - Getting up and running](https://docs.nestjs.com/controllers#getting-up-and-running)

## 官方内容讲解

定义好 `CatsController` 和它的路由后，Nest 还不会自动发现这个类。控制器必须登记到某个模块的 `controllers` 数组中，应用启动时 Nest 才会创建并挂载它。

官方示例只定义了根模块 `AppModule`，因此直接在它的 `@Module()` 元数据中登记 `CatsController`。本节关注的是“控制器如何进入应用”，不是控制器路由元数据本身。

## 学习版调用过程

1. `@Controller('cats')` 将控制器标记和 `cats` 路径元数据写到控制器类上；`@Get()` 为处理方法写入路由元数据。这些装饰器描述控制器和路由，但不会单独创建实例或注册路由。
2. `@Module({ controllers: [...] })` 将控制器列表写到模块类上。学习版的 [Module 装饰器](../../@nest/common/decorators/modules/module.decorator.ts)负责保存这份元数据。
3. [NestFactory.create()](../../@nest/core/nest-factory.ts) 从传入的根模块读取 `controllers` 元数据。学习版在 `app.init()` 时实例化列表中的控制器、扫描它们的路由并注册到 HTTP 适配器；`listen()` 会先触发 `init()`。
4. 当模块的 `controllers` 是空数组时，控制器实例列表和发现的路由也都是空的。请求 `/cats` 没有匹配的路由，因此 Express 返回 `404`。

学习版当前只读取传入的根模块，不递归处理 `imports`。这与本节示例只通过根 `AppModule` 注册控制器的范围一致；模块导入和完整模块扫描不属于本节。
