# Property-based injection：学习锚点与进度

官方章节：[Providers - Property-based injection](https://docs.nestjs.com/providers#property-based-injection)

## 官方内容讲解

除构造函数注入外，也可以用 `@Inject()` 把依赖注入类属性。官方指出，这在基类需要依赖、又不想让每个子类都通过 `super()` 传递依赖时更方便；如果没有继承场景，优先使用构造函数注入，因为依赖声明更显式。

官方示例使用字符串 token `'HTTP_OPTIONS'`，其注册方式属于 Custom providers 详细内容。

## 学习版实现与验证

- `@Inject(CatsService)` 已记录属性名和 class token 到 `PROPERTY_DEPS_METADATA`，并从公共装饰器入口导出。
- [NestFactory](../../@nest/core/nest-factory.ts) 先创建所有 Provider 实例，再读取其属性依赖并赋值；创建 Controller 后也复用同一逻辑。
- [property-injection.e2e-spec.ts](../../test/2_Providers/7_property_based_injection/property-injection.e2e-spec.ts) 验证 Controller 属性注入 `CatsService`。
- [provider-property-injection.e2e-spec.ts](../../test/2_Providers/7_property_based_injection/provider-property-injection.e2e-spec.ts) 验证 `CatsService` 的属性注入 `CatsDataService`，再由 Controller 调用并返回 `['Milo']`。
- 用户报告两份测试均通过：2 个测试文件、2 项测试通过。

## 当前范围与边界

- 本节测试使用 class token；字符串 token 和自定义 Provider 注册留待 Custom providers。
- Controller 与模块中登记的 Provider 实例都支持属性注入；继承属性场景尚未单独验证。
- `readPropertyDependencies()` 现在会校验每项都包含字符串或 symbol 属性键，以及函数类型 token；无效元数据会报错。本次 HTTP 用例验证正常注入路径，没有单独覆盖无效元数据报错路径。
- 官方由 Injector 的属性依赖解析和 `applyProperties()` 处理实例；学习版将它简化为 `NestFactory` 中 Provider、Controller 的创建后赋值。
